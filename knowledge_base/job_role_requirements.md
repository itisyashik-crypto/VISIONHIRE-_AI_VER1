# Job Role Requirements

## How to Apply
These role profiles are starting templates, not universal job descriptions. Confirm seniority, domain, tools, and essential criteria with the hiring manager before screening. Consider equivalent skills and adjacent experience. Score only role-related evidence; do not infer ability from demographics, employer prestige, or resume polish.

## Data Analyst
- **Role overview:** turn structured data into reliable analysis and decisions.
- **Responsibilities:** query and validate data; define metrics; analyze trends; build reports; communicate limitations.
- **Required skills:** SQL, data quality, analytical reasoning, clear communication.
- **Preferred skills:** Python, statistics, experimentation, domain knowledge.
- **Tool stack:** SQL warehouse, Python or R, Excel, Power BI/Tableau, version control.
- **Certifications:** Power BI/Tableau credentials may support tool-specific roles; not mandatory by default.
- **Expected projects:** validated analysis, repeatable reporting, or dashboard linked to a real decision.
- **Interview topics:** joins, aggregation, metric definitions, data quality, chart choice, uncertainty.
- **Recruiter expectations:** evidence of careful analysis and understandable recommendations.
- **Readiness signals:** explains assumptions, validates inputs, and ties findings to decisions.
- **Common gaps:** unsupported metrics, no data validation, confusing correlation with causation.
- **Evaluation criteria:** SQL and data handling; analytical rigor; communication; project ownership.

## Business Analyst
- **Role overview:** connect stakeholder needs, business processes, and delivery teams.
- **Responsibilities:** discovery, requirements, process mapping, acceptance criteria, traceability, change analysis.
- **Required skills:** structured communication, requirements elicitation, analytical thinking, documentation.
- **Preferred skills:** SQL/BI, Agile, domain expertise, process modeling.
- **Tool stack:** Jira/Azure DevOps, process/modeling tools, spreadsheets, collaboration suites.
- **Certifications:** IIBA ECBA/CCBA/CBAP or Agile credentials where relevant to scope.
- **Expected projects:** validated requirements, process improvement, or measurable workflow change.
- **Interview topics:** ambiguity, stakeholder conflict, prioritization, acceptance tests, change control.
- **Recruiter expectations:** translates needs into testable outcomes without losing context.
- **Readiness signals:** asks clarifying questions and makes assumptions and trade-offs explicit.
- **Common gaps:** solution jumping, vague requirements, no validation with users.
- **Evaluation criteria:** discovery, analytical structure, stakeholder alignment, delivery traceability.

## Data Scientist
- **Role overview:** use statistical and computational methods to answer questions or build predictive analyses.
- **Responsibilities:** frame problems, explore data, design experiments, build and validate models, communicate uncertainty.
- **Required skills:** Python/R, statistics, SQL, evaluation, data storytelling.
- **Preferred skills:** causal inference, NLP/CV, cloud platforms, deployment awareness.
- **Tool stack:** pandas, scikit-learn or equivalent, notebooks, SQL, experiment tracking, visualization.
- **Certifications:** relevant platform credentials may help; practical validation evidence is stronger.
- **Expected projects:** reproducible analysis or model with baselines, holdout evaluation, and error analysis.
- **Interview topics:** leakage, sampling, metrics, calibration, confounding, experiment design.
- **Recruiter expectations:** explains when a model is useful and when it is not.
- **Readiness signals:** begins with a baseline and relates evaluation to decision costs.
- **Common gaps:** overfit results, weak data provenance, no deployment or impact limitations.
- **Evaluation criteria:** statistical reasoning, coding, domain framing, validation, communication.

## ML Engineer
- **Role overview:** build reliable software systems that train, serve, and monitor machine-learning models.
- **Responsibilities:** data/feature pipelines, training and evaluation workflows, serving, monitoring, reproducibility, incident response.
- **Required skills:** software engineering, Python or equivalent, model evaluation, APIs, data workflows.
- **Preferred skills:** distributed systems, containers, cloud, feature stores, specialized ML infrastructure.
- **Tool stack:** Python, scikit-learn/PyTorch/TensorFlow as role requires, CI/CD, containers, cloud, monitoring.
- **Certifications:** cloud ML or platform credentials when the target environment requires them.
- **Expected projects:** reproducible model service with versioning, tests, monitoring, and rollback.
- **Interview topics:** feature leakage, deployment trade-offs, latency, drift, observability, failure handling.
- **Recruiter expectations:** balances model quality with operational and product constraints.
- **Readiness signals:** discusses data and model lifecycle, not only offline accuracy.
- **Common gaps:** no monitoring, irreproducible training, weak software testing.
- **Evaluation criteria:** engineering quality, ML lifecycle understanding, reliability, security, collaboration.

## Software Engineer
- **Role overview:** design, implement, test, and maintain software that solves user or business problems.
- **Responsibilities:** clarify requirements, deliver code, test, review, operate, and improve systems.
- **Required skills:** programming fundamentals, debugging, testing, collaboration, maintainability.
- **Preferred skills:** domain framework, cloud, distributed systems, accessibility/security as relevant.
- **Tool stack:** language-specific framework, Git, CI, test framework, issue tracking, observability.
- **Certifications:** typically optional unless required by a regulated or vendor-specific environment.
- **Expected projects:** maintainable application or service with tests and clear trade-offs.
- **Interview topics:** coding, data structures relevant to work, design, testing, debugging, security.
- **Recruiter expectations:** explains decisions, limitations, and individual contribution.
- **Readiness signals:** decomposes problems, verifies behavior, and considers failure cases.
- **Common gaps:** happy-path-only implementation, no tests, unclear ownership.
- **Evaluation criteria:** problem solving, code quality, design judgment, delivery, communication.

## Backend Developer
- **Role overview:** build APIs and services that process data and support application behavior.
- **Responsibilities:** API design, persistence, business logic, security, performance, observability, operations.
- **Required skills:** backend language, HTTP/API fundamentals, data stores, testing, security basics.
- **Preferred skills:** messaging, caching, containers, distributed systems, cloud.
- **Tool stack:** Python/Java/Node or role language, SQL/NoSQL, API framework, CI, monitoring.
- **Certifications:** cloud or framework credentials where relevant; not universal requirements.
- **Expected projects:** tested API with validation, authentication/authorization, persistence, and operational notes.
- **Interview topics:** schema design, idempotency, transactions, rate limits, failures, API versioning.
- **Recruiter expectations:** builds reliable interfaces and considers consumers and operations.
- **Readiness signals:** discusses validation, security, observability, and failure modes.
- **Common gaps:** unsafe input handling, missing tests, unexamined consistency or retry behavior.
- **Evaluation criteria:** implementation, API/data design, security, reliability, maintainability.

## Frontend Developer
- **Role overview:** build usable, accessible, responsive client experiences.
- **Responsibilities:** implement interfaces, state/data flow, accessibility, testing, performance, and cross-browser behavior.
- **Required skills:** HTML, CSS, JavaScript/TypeScript, browser fundamentals, responsive design.
- **Preferred skills:** React/Vue/Angular, design systems, accessibility testing, build tooling.
- **Tool stack:** TypeScript/JavaScript, component framework, browser devtools, testing, Git, CI.
- **Certifications:** usually optional; a working, accessible portfolio is more informative.
- **Expected projects:** responsive interface with meaningful state, tests, and accessible interaction.
- **Interview topics:** semantic HTML, async state, rendering, accessibility, performance, component design.
- **Recruiter expectations:** balances visual intent, user needs, and robust behavior.
- **Readiness signals:** explains keyboard/accessibility behavior, errors/loading, and responsive decisions.
- **Common gaps:** inaccessible controls, fragile state, no loading/error states, untested layouts.
- **Evaluation criteria:** browser skills, UX implementation, accessibility, quality, collaboration.

## Full Stack Developer
- **Role overview:** deliver coordinated frontend and backend functionality across an application boundary.
- **Responsibilities:** UI, APIs, data persistence, integration, testing, security, and release support.
- **Required skills:** one frontend and one backend stack, HTTP, data modeling, testing, Git.
- **Preferred skills:** cloud deployment, CI/CD, observability, accessibility, product discovery.
- **Tool stack:** web framework, API framework, database, browser tooling, test suite, deployment platform.
- **Certifications:** platform-specific credentials only where relevant.
- **Expected projects:** end-to-end feature with validation, authorization, tests, and deployment documentation.
- **Interview topics:** API/UI contracts, data flow, authentication, failure handling, deployment trade-offs.
- **Recruiter expectations:** identifies depth honestly and collaborates across specialist boundaries.
- **Readiness signals:** handles end-to-end flows and explains where deeper specialization is needed.
- **Common gaps:** shallow treatment of security, persistence, or accessibility across the stack.
- **Evaluation criteria:** integration quality, breadth appropriate to level, sound boundaries, testing.

## DevOps Engineer
- **Role overview:** improve software delivery and operational reliability through automation and platform practices.
- **Responsibilities:** CI/CD, infrastructure automation, observability, incident response, developer enablement, security controls.
- **Required skills:** Linux, networking, scripting, cloud/infrastructure basics, automation, operational judgment.
- **Preferred skills:** Kubernetes, Terraform, policy-as-code, SRE methods, major cloud platforms.
- **Tool stack:** GitHub Actions/GitLab CI, Docker, Kubernetes, Terraform, cloud monitoring/logging.
- **Certifications:** CKA/CKAD or cloud credentials may be relevant to a specific environment.
- **Expected projects:** automated deployment with tests, least privilege, monitoring, and rollback.
- **Interview topics:** release failure, secrets, capacity, incident response, recovery, toil reduction.
- **Recruiter expectations:** treats reliability and security as design concerns, not afterthoughts.
- **Readiness signals:** explains deployment risk, observability, rollback, and learning after incidents.
- **Common gaps:** automation without controls, no recovery plan, tool familiarity without operational reasoning.
- **Evaluation criteria:** automation, reliability, security, incident judgment, developer collaboration.

## Cloud Engineer
- **Role overview:** design, provision, secure, and operate cloud infrastructure aligned to workload needs.
- **Responsibilities:** architecture, identity, networking, provisioning, resilience, cost, governance, and operations.
- **Required skills:** cloud fundamentals, networking, IAM/security, automation, monitoring.
- **Preferred skills:** AWS/Azure/GCP depth, Kubernetes, data platforms, compliance domain.
- **Tool stack:** major cloud services, Terraform or equivalent, containers, monitoring, CI/CD.
- **Certifications:** role-level AWS/Azure/Google Cloud credentials can structure learning and validate platform familiarity.
- **Expected projects:** deployed architecture with infrastructure as code, access controls, monitoring, and cost/recovery notes.
- **Interview topics:** network boundaries, least privilege, availability zones, backup, scaling, cost and threat modeling.
- **Recruiter expectations:** makes trade-offs explicit and designs for operations and security.
- **Readiness signals:** can explain failure recovery and identity boundaries, not just service names.
- **Common gaps:** over-permissioned identities, untested recovery, no cost or observability plan.
- **Evaluation criteria:** architecture, security, automation, resilience, governance, cost awareness.
